Quick start
Two commands to first station. Setup shows a plan before it installs any playback tools.

  

    
npm · Node.js 22+
$ npm install -g @ciphore/radiocli
$ radiocli setup
$ radiocli

    
Homebrew · macOS
$ brew install ciphore/tap/radiocli
$ radiocli
Also installs Node.js, mpv, and FFmpeg.

    
Just try it
$ npx @ciphore/radiocli
No install. Run radiocli doctor to check your audio player.

Explore world

  

    
Spin the globe from your keyboard

    
A braille world map sits next to the station list. Move one scan cursor and the list reloads around that coordinate, sorted by real distance.

    
  • WASD to nudge, Shift+WASD to jump, or click the map
  • Distance-truthful, not popularity-first
  • Cached station atlas keeps working during directory outages
  • Nearby tab lists stations around your approximate location

Search

  

    
Find any station in seconds

    
Search by station name or genre, then narrow by country, language, codec, and bitrate. Browse whole country lists when you just want to wander.

    
$ radiocli search ambient --codec MP3 --min-bitrate 128
$ radiocli play --country JP

Library

  

    
Your stations stay yours

    
Favorites, recent stations, and imported streams in one place — on your machine, not somebody’s cloud.

    
  • Add any direct HTTP(S) stream URL with ICY metadata lookup
  • Import M3U, PLS, or XSPF; export an M3U library
  • Track history and named presets: radiocli play work
  • JSON backup and restore

Receivers

  

    
424 displays. One honest signal.

    
Braille animation, ASCII geometry, waves, fire, cityscapes, a spinning donut. Switch styles and 48 color themes without interrupting playback.

    
Receivers only move when audio is actually playing. Paused, loading, or broken streams show a flat zero-signal frame — the display never fakes it.

    
  • Full, compact, and micro layouts follow your window size
  • Reduced motion, screen-reader output, NO_COLOR, ASCII-only
  • Keyboard, mouse, and trackpad

    Try all 424 receiver styles →

    






  
Alarms (beta)

  

    
Wake up to a station, not a beep

    
One-time or recurring schedules with timezones, independent volume, fade-in, fallback stations, snooze, and auto-stop. Native OS scheduling means the terminal doesn’t have to stay open.

    
  • launchd · Task Scheduler · systemd user timers
  • “Verify alarm setup” rehearses the whole path
  • Sleep timer for the other end of the day

    
Beta: keep a second alarm for anything critical.

Agent control

  

    
“Play something with birds.”

    
An optional Model Context Protocol server gives your coding assistant typed tools for discovery, playback, favorites, stats, alarms, AirPlay, and appearance.

    
$ radiocli setup --mcp

    
  • Opt-in, local, stdio transport
  • Agents can only play library stations or RadioCLI’s own search results — no arbitrary URLs
  • radiocli agent offers the same controls without MCP

Playback
Pause, volume, mute, and live track metadata through mpv, with media keys and a sleep timer. ffplay and VLC as fallbacks.

    
Stream recovery
Directory mirrors, broken-stream skipping, cached lists, offline browsing, and a low-bandwidth mode.

    
AirPlay (experimental)
Discover network receivers and switch audio output from the TUI, passcodes included.

FAQ

  
radiocli help --all

What is RadioCLI?
RadioCLI is a free, open-source internet radio player that runs in your terminal. It has a full-screen terminal interface (TUI) for browsing and listening, and a scriptable command line for starting, pausing, and switching stations from your shell.


How do I install RadioCLI?
With Node.js 22 or newer: npm install -g @ciphore/radiocli, then radiocli setup. On macOS, brew install ciphore/tap/radiocli also installs Node.js, mpv, and FFmpeg. To try it without installing, run npx @ciphore/radiocli.


Do I need an account or subscription?
No. There is no account, no sign-in, and no cloud library. Favorites, recent stations, settings, track history, and listening stats are stored on your machine, with JSON backup and restore.


Which operating systems are supported?
macOS (Apple silicon and Intel), Ubuntu Linux (x64 and arm64), and Windows (x64 and arm64) are tested in CI on Node.js 22 and 24. FreeBSD, OpenBSD, and NetBSD are supported for the core package route. Other platforms such as Alpine, WSL, and Termux are experimental.


What do I need for audio playback?
RadioCLI plays streams through mpv, which provides pause, volume, mute, media keys, and live track metadata. ffplay and VLC work as playback-only fallbacks. radiocli setup shows a plan and helps install the tools for your system; radiocli doctor checks what is available.


Where do the stations come from?
Station discovery uses the public Radio Browser directory, with cached results that stay available during provider outages. You can also add any direct HTTP(S) stream URL and import M3U, PLS, or XSPF playlists.


Can an AI assistant control RadioCLI?
Yes, if you opt in. radiocli setup --mcp registers a local Model Context Protocol (MCP) server with typed tools for discovery, playback, favorites, stats, alarms, AirPlay, and appearance. It runs over stdio on your machine, and agents can only play stations from your library or from RadioCLI's own search results.


Can RadioCLI wake me up with a radio station?
Alarms are in beta. You can schedule one-time or recurring alarms with timezones, fade-in, fallback stations, snooze, and auto-stop. They register with launchd, Task Scheduler, or a systemd user timer, so the terminal does not need to stay open. Use a second device for anything critical.


What does RadioCLI send over the network?
It resolves public stream URLs and hands playback to your local player; it does not proxy audio. Nearby uses an approximate IP-based location lookup only when you open that screen, and you can turn it off in Settings. Explore uses only the map cursor you move.


Is RadioCLI free?
Yes. RadioCLI is MIT licensed and the source is on GitHub at Ciphore/RadioCLI.
